Hi Dr.Maxy,

About the minimized UI (UiUnitselectionMIN): the new DLL key is minUIStats. Four points are now decided,
and two questions are left for you.

Decided:

1. Row places: the rows start from the original minimized UI (uiunitselectionmin.xml from Data3.bar),
   with a few new gadgets added at the top level, never inside a gadget the game shows or hides. So
   Speed no longer depends on the Armor value. The places are only a proposal: the rows are listed in a
   data file (minuirows.xml), so you can move or remove them, or add new ones, without a new DLL.

2. Building armor: shown in the original "Resists" spot, with the same look as for units. The game
   showed it only for protos of type Unit; with the key, any proto with an armor above 0 shows it.

3. Speed: the live speed (with techs, snares and auras), as the big UI shows it, not the base speed of
   {currentUnitMaxVelocityFloat}. It is also a text you can put in any gadget: {uhcSpeed}.

4. More than 3 attacks: the minimized UI only had room for 3 attack rows. Extra rows now show the
   rest, and the other rows of the big UI the minimized one never had (Gatherers, Group Health).

Questions:

5. In your current uiunitselectionmin.xml, the gadget unitselectionpanel-unitTypeName (line 40) has no
   "/>" and no closing tag of its own. So nearly the whole panel (hit points, resists, resources, the
   attack rows, the health bars) ends up as its child, and the extra "</gadget>" at line 88 closes the
   panel. The game copes with it, but is it intended? Our proposal starts from the original file, so it
   does not depend on it.

6. Your uiunitstatpanel3.xml (the big UI's stat panel) holds the original minimized stat panel: 5 rows
   instead of 9. So the big UI shows only one attack row (a Musketeer shows "Ranged ATK" but not its
   Siege and Hand attacks). Is that intended, or should it have the original 9 rows?

The files are in min-ui: README.txt explains how to install and change them.
