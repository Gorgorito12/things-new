   The four live guardians in range were all refused because the tactic gives them another

2. One DLClegendarybeast1 (5000 HP guardian), the same power, three casts with hardware
   breakpoint traces (a0-traces.txt; a0-trace-tool.py, pinned to the bed's own pid).
   [O] Each cast: one attack cycle; the first Attack tag 489 ms after the cycle starts (test 1),
   the three tags 208-212 ms apart (traces), all in state 1; only the first fires. The beast lost
   750 HP per cast, not 2250. Video: a0-stock-cast.mp4, sheet a0-stock-cast-sheet.jpg (three
   muzzle flashes and shot sounds, one hit).
   [O] Why: a power-launched attack keeps its power use at [ua+6Ch] (here 0x130B0004), whose
   [+1Ch] is the ability record (99). Every Attack tag of such an attack goes 0x48F7E4 ->
   0x48EA3D -> 0x6EDB7E(unit, record, ...) -> 0x4B7766 (test al,al / jne 48F7F1h, else 0x48CF7B,
   no shot). 0x6EDB7E answered 1 at the first tag and 0 at the second and third (the power's
   recharge starts with the first shot). After the first shot the unit action also gets its
   flag 6 (0x48F12B, SetFlag 0x470F76).
   So today "Hammer Fanning" and "Slip Hammering" fire ONE shot per use; the other two tags are
   only a flash and a sound. <numberprojectiles>3</numberprojectiles> is not read by the exe.

Timing [O]: the attack animation plays at rate (0.90 + 2.0) / 4.5 = 0.644 (attack clip 0.90 s,
reload clip 2.0 s, ROF 4.5), i.e. 1.552 s real per clip second; the Attack tag values are fractions
of the clip (0.35 x 0.90 s x 1.552 = 0.489 s, measured 489 ms; 0.15 apart = 210 ms, measured
208-212 ms). Game time; the test game ran near 1x.

What a DLL change needs [I, from the above]:
  a) more than one shot per use: for a tagged power attack, the Attack tags after the first one of
     the same cycle must pass the power check at 0x4B7766 (only 0x48EA9D jumps there; no branch
     lands in 0x4B7767..0x4B776D; capstone scan of the stock exe). A new hook, 8 bytes, there.
  b) retargeting: retargetInAction must accept a candidate by the running action's own <rate>
     types when the attack is power-launched ([ua+6Ch] != 0), instead of 0x489ECC's answer.
Without (a), (b) alone changes nothing: the next tags fire no shot anyway.
